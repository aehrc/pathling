# Evidence

The measurements the decisions of this specification rest on, each with a runnable reproduction.
The Java probes run with [run-probe.sh](run-probe.sh) after `io` is built, as each record says.

| Record                                     | Reproduction                                         | Decision it supports                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------ | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [decimal-read.md](decimal-read.md)         | [decimal-read-probe.java](decimal-read-probe.java)   | T003, research R3: the inferred JSON read gives a decimal a data-dependent type, so the defined read takes a decimal as `string` and a decimal's parity is equality in value (gate B).                                                                                                                                                  |
| [stream-safety.md](stream-safety.md)       | [stream-safety-probe.java](stream-safety-probe.java) | T002, research R4 and R5: `from_json`, the bundle splitters with `explode`, and `from_xml` need no action and run over a stream, while `spark.read().json(Dataset<String>)` fails over one, so a defined read of a dataset uses `from_json`.                                                                                            |
| [field-order.md](field-order.md)           | [field-order-probe.py](field-order-probe.py)         | Research R14: Parquet, Delta and catalog tables match fields by name at every depth, so field order does not count towards whether a defined schema is acceptable, and a defined read keeps the given order.                                                                                                                            |
| [yaml-defined-run.md](yaml-defined-run.md) | The command it records                               | T043: the baseline of the YAML suites under today's inferred loads, which slice 06 (T048) compares the defined loads with.                                                                                                                                                                                                              |
| [absence-coverage.md](absence-coverage.md) | `AbsentElementTest`                                  | T041 and SC-005: the absence tests cover every position kind, and T042 adds the two gaps it names, a metadata group inside a repeating element and both sides of a combination.                                                                                                                                                         |
| [nullability.md](nullability.md)           | [nullability/](nullability/) (`run.sh`)              | Research R15 and FR-008: Spark's file and JSON readers make every field nullable while Delta, catalog tables and datasets keep their flags, a false `NOT NULL` flag gives wrong results, and a load-time `NOT NULL` check runs only where its column is evaluated, so a read with a schema passes the source's own nullability through. |
