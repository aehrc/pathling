## Comments

### What the re-plan adds to the documentation (owner, 2026-11-02)

- *Fill* keeps a stored annotation that is null, so a table merged from annotated and unannotated sources needs *recompute*. Deciding *fill* per row moved to a GitHub issue after #2367 (ticket 38).
- Encoding a streaming dataset is refused in this release. A stream is encoded batch by batch, for example in `foreachBatch`. Dense mode and streaming encode moved to a GitHub issue after #2367 (tickets 18 and 19).
- If tickets 17 and 52 land, the primitive metadata group, its ingest option, and its navigation from FHIRPath, which is always on (ticket 54, Primitive metadata always on, decision 154; owner, 2026-11-13), so the documentation names no switch for it and does not say it is off by default.

### Implementation (2026-11-16, branch `issue/2832_15`)

- **Plan test.** Each kind already has one, written by the tickets that landed it: `DecimalCollectionTest.decodingTakesTheAnnotationWhereTheSchemaCarriesIt` (numeric), `DateRangeComparisonTest.comparisonTakesTheStoredRangeWhereTheSchemaCarriesIt` (range), and `QuantityCollectionTest.comparisonWithALiteralComputesNoCanonicalFormForTheLiteral` with `QuantityNumericAnnotationTest.theValueTakesTheAnnotationWhereTheSchemaCarriesIt` (canonical), with `AnnotationPlanBaselineTest` pinning the plans. Each compares the plan over an annotated input with the plan over the same data unannotated. New: `AnnotationDecidedBySchemaTest` proves the choice is not made per row, for each kind: a copy of an annotated table with one row's annotations set to null, as a table merged from annotated and unannotated sources holds them under *fill* (#2923), does not match that row, where the same data without the annotation in the schema does.
- **SC-004.** Covered without a new suite. The engine suites (fhirpath.js and FHIRPath Lab YAML, DSL, views, search) build their data with `PofDatasets`, through `FhirReader`, which adds no annotations, so the whole engine suite runs over annotation-free data, the schema a write with every annotation disabled stores. `AnnotationFreeSuiteTest` (T089) asserts that premise: the fixtures, the conformance corpora and files written to Parquet carry no annotation at any depth, with a control that the check can fail; its stale M5 Javadoc is revised. The round trip through Parquet with every kind disabled is covered by the `disabled` paths of `DecimalCollectionTest`, `DateRangeComparisonTest` and `MetadataOnlyPrimitiveSearchTest`.
- **Docs.** `site/docs/libraries/io/schema.md` gains an Annotations section: the three kinds, their fields, switches and defaults, the timestamp setting, the decision from the schema and the merged-table case (#2923), the annotation step with *fill*, *recompute*, keep and drop, and the streaming refusal (#2881). The stale sentence is gone, primitive metadata navigation is described as always on with no switch, and the `unsignedInt`/`positiveInt` deviation is documented. The Python, R and Java docs of `recompute_annotations` describe the merged-table case, and the Python and R docs of `spark` say the timestamp warning applies where range annotations are enabled. The R `man/` pages are generated by the build (`roxygen2::roxygenise()` in `process-sources`) and are not tracked.
