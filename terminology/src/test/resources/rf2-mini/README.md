# rf2-mini test fixture

A small, synthetic SNOMED CT RF2 snapshot release used by the local terminology
tests. It is not derived from any real SNOMED CT content: the clinical concepts
carry synthetic (but structurally valid, Verhoeff-checked) short-format SCTIDs,
while the metadata identifiers (module, description types, acceptability, is-a
and attribute types, association reference set) are the real International
metadata SCTIDs so that a real terminology server can load the same files for
differential testing.

The fixture is generated by [`generate.ts`](generate.ts); it is deterministic,
so regenerating with the same inputs reproduces byte-identical files and the
well-known codes below stay stable. Regenerate with:

```bash
bun run terminology/src/test/resources/rf2-mini/generate.ts
```

The files use tab-delimited columns and CRLF line endings, exactly as a real RF2
release does. A `.gitattributes` rule preserves those line endings across
checkouts.

## Releases

Two snapshot releases of `http://snomed.info/sct` are provided, both in the
International core module (`900000000000207008`):

| Directory                 | Version                | Concepts (active) | Notes                       |
| ------------------------- | ---------------------- | ----------------- | --------------------------- |
| `international-20230601/` | `.../version/20230601` | 200 (199)         | Base release.               |
| `international-20240601/` | `.../version/20240601` | 201 (200)         | Adds `GESTATIONAL_SUBTYPE`. |

Each release has the standard package layout:

```text
<release>/Snapshot/
├── Terminology/
│   ├── sct2_Concept_Snapshot_INT_<date>.txt
│   ├── sct2_Description_Snapshot-en_INT_<date>.txt
│   └── sct2_Relationship_Snapshot_INT_<date>.txt
└── Refset/
    ├── Language/der2_cRefset_LanguageSnapshot-en_INT_<date>.txt
    └── Content/
        ├── der2_Refset_SimpleSnapshot_INT_<date>.txt
        └── der2_cRefset_AssociationSnapshot_INT_<date>.txt
```

The detected edition/version is `http://snomed.info/sct/900000000000207008/version/<date>`.
Importing the same release twice under differing `editionUri` overrides creates
two editions of the one code system URL, which the version-resolution tests use
to exercise default-edition preference and multi-edition ambiguity.

## Content graph

`ROOT` below is `138875005 |SNOMED CT Concept|`. Arrows point from child to
parent (is-a). All concepts are active unless marked inactive.

```text
138875005 (SNOMED CT Concept)
├── ROOT_FINDING
│   └── DISORDER
│       ├── DIABETES  (defined; finding site → PANCREAS, morphology → DEGENERATION)
│       │   ├── TYPE1_DIABETES  (defined; finding site → PANCREAS)
│       │   ├── TYPE2_DIABETES  (defined; finding site → PANCREAS; extra acceptable synonym "T2DM")
│       │   │   └── TYPE2_WITH_COMPLICATION
│       │   ├── GESTATIONAL_DIABETES
│       │   │   └── GESTATIONAL_SUBTYPE  (20240601 release only)
│       │   ├── DIABETES_INACTIVE  (inactive; SAME AS → TYPE2_DIABETES)
│       │   └── DIABETES_FILLER_1 .. DIABETES_FILLER_90
│       ├── HYPERTENSION
│       └── DISORDER_FILLER_1 .. DISORDER_FILLER_95
├── BODY_STRUCTURE
│   └── ENDOCRINE_STRUCTURE
│       └── PANCREAS_STRUCTURE
├── MORPHOLOGY_TOP
│   └── DEGENERATION_MORPH
└── SIMPLE_REFSET  (identifies the simple reference set below)
```

Features exercised by the fixture:

- **Hierarchy depth**: `138875005 → ROOT_FINDING → DISORDER → DIABETES →
TYPE2_DIABETES → TYPE2_WITH_COMPLICATION` is five levels below the root.
- **Attribute relationships with role groups**: the finding-site and
  associated-morphology relationships sit in role group 1 (retained for fidelity
  but not queried in v1).
- **Reference sets**: a simple reference set (`SIMPLE_REFSET` containing
  `TYPE1_DIABETES`, `TYPE2_DIABETES`, `GESTATIONAL_DIABETES`), the US English
  language reference set (`900000000000509007`, ranking descriptions), and a
  SAME AS association reference set (`900000000000527005`) mapping the inactive
  concept to its replacement. Three filler concepts (`1099005`, `1139006` and
  `1159005`) are associated with the same target, so that reverse translation
  returns several results and their order is observable. Their rows are written
  in an order that is neither ascending nor descending by source code, although
  the importer does not carry that order into the store - it resolves reference
  set rows against the concept dictionary with a join that streams the
  dictionary, so they land in concept code order regardless.
- **Inactive concepts**: `DIABETES_INACTIVE` is inactive and is excluded from
  implicit value set membership but remains resolvable for lookup.
- **Designations**: `TYPE2_DIABETES` carries an extra acceptable synonym so
  designation filtering by acceptability can be tested.
- **Rows that do not resolve**: `138875005` is the is-a parent of the four
  top-level concepts but is not itself shipped in the concept file, so four
  relationship rows have no destination concept to attach to. This is what the
  base release's resolution figures below reflect.

## Resolution figures of the base release

The importer reports, per file, how many of its active rows resolved against the
concept dictionary. `SnomedRf2ImporterTest` asserts these figures for
`international-20230601`, so a regeneration that changes the fixture's shape
means updating that test:

| File                                     | Resolved | Active rows |
| ---------------------------------------- | -------- | ----------- |
| `sct2_Description_Snapshot-en_INT_*`     | 401      | 401         |
| `sct2_Relationship_Snapshot_INT_*`       | 199      | 203         |
| `der2_Refset_SimpleSnapshot_INT_*`       | 3        | 3           |
| `der2_cRefset_AssociationSnapshot_INT_*` | 4        | 4           |

The concept file, the language reference set and (where a test adds one) the
Module Dependency reference set produce no figures, because none of them is
resolved against the concept dictionary. Tests derive further shapes from these
releases at run time rather than checking in more trees; `SnomedRf2ImporterTest`
carries the helpers that copy a release and then truncate, split, append to,
deactivate or duplicate one of its files.
